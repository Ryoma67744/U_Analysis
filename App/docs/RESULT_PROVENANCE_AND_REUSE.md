# 結果の由来、出力、PreFlight後の解析（ver77.0）

ファイル名がHarmonyでも、実体が未補正PCAである旧結果があります。また、PCAの座標にHarmonyのクラスタを投影した結果は、PCAで独立にクラスタリングした結果とは異なります。ver77.0ではRDS内部のreduction、assay、計算履歴と保存記録を照合します。クラスタ番号が同じという理由だけで誤計算とは判定しません。

## 閲覧と出力

- 候補一覧は軽量なファイル探索です。選択時に内容を検証し、実際の手法・クラスタ由来・座標種別を確定します。ファイル名は候補探索にだけ使います。
- 計算由来は `recorded`（記録あり）、`inferred`（内容から整合した推定）、`unknown`、`conflict` を区別します。来歴が不明な結果を独立PCAやHarmonyとして比較出力しません。
- PCAの第1・第2主成分の表示はPC1/PC2です。UMAPがない結果をUMAP計算済みとは表示しません。
- UMAPとSpatialは同じクラスタ割当を使います。出力開始時に手法、割当、座標、名前・結合定義、選択範囲を固定し、途中で表示手法を変えても出力元は変わりません。
- 出力前後のSHA-256検査で、同サイズ・同更新時刻のファイル差替えも検出します。大きなRDSの初回検証と再確認には読み取り時間が必要です。
- 元RDSと画素の対応が欠ける、重複する、必要な手法が存在しない場合は、部分的な成功として公開せず理由を表示します。手法が実際に解析していない画素はnullとして区別します。

単一手法UMAPのParquetでは従来の `UMAP cluster`、`UMAP_1`、`UMAP_2` を使います。複数手法では `PCA__UMAP_1`、`Harmony__UMAP_1`、`RPCA__UMAP_1` などを使い、共通UMAP列を自動生成しません。PC表示は `PC_1`、`PC_2` です。Arrow schema metadataの `ua_column_roles` と `ua_export_manifest` に、成果物のID/hash、列のroles、選択範囲と照合結果を保存します。新形式の強度列はrolesで指定された列だけを読み、末尾 `_1` などをm/zとして解釈しません。

## PreFlightと実行操作

1. 「reductionのみ作成」で上流計算を保存します。
2. PreFlight診断で保存次元と推奨値を確認します。自動推奨はdims・n.neighborsを対象とし、min.dist・metric・クラスタ条件の最適化を意味しません。
3. 保存時の条件を守って続きを行う場合は「保存条件で続きを実行」を使います。
4. 推奨値や手動値を採用する場合は「保存済みPCA等から現在の条件で下流解析」を使います。UMAPには入力欄の条件を、クラスタには個別欄の指定値を使います。クラスタ欄の空欄は元の保存条件を引き継ぎます。

新しい下流解析は別フォルダに保存します。同名フォルダがあれば連番を付けます。保存PCAが20PCで要求が30次元の場合はエラーにし、自動で20へ切り詰めません。20へ変更するか、上流から作り直してください。旧クラスタの名前・結合・DEGを新クラスタへ無条件に適用しません。

`analysis_methods.json` schema 2ではreduction、umap、cluster、deg、exportの状態と内容hashを別々に保存します。作図に失敗しても、検証して保存済みのクラスタを未計算へ戻しません。上流計算、UMAP、クラスタ、DEGの署名は分離し、下流の変更だけでPCAを作り直すことを避けます。

サブプロジェクトの `result_refs.reduction` は診断・再利用用、`result_refs.analysis` は閲覧・出力用です。新しいPreFlightだけで閲覧用参照を置き換えません。別プロジェクト・別実行の手法を自動合成しません。

## 旧形式を検証して取り込む

診断だけなら元結果を変更しません。以下はアプリと同じPython/R環境で、`App` ディレクトリから実行する例です。パスとIDは実際のものへ置き換えてください。

```sh
python -m app.services.legacy_result_import /data/old_run --report /data/audit.json
python -m app.services.legacy_result_import /data/old_run --import-to /data/verified_import --method PCA
```

取込先は元結果の外にある未作成フォルダに限定します。選択した全手法のRDSを内容検証してコピーし、コピーと元ファイルのSHA-256が一致した場合だけ取込フォルダを公開します。元RDS、旧署名、元の解析条件を保持し、当時のRDSへ新しい計算済みの印を書き戻しません。条件記録やreductionの由来が確認できない場合は上流からの新規解析を案内します。

複数手法の同時取込には、同じCellID集合に加え、RDS内部の実行ID・計算署名と内容SHAに結び付いた保存記録から、共通の入力・実行であることを確認します。CellIDやフォルダ名だけが一致する旧結果、異なる画素集合の結果は混在させず、`--method PCA` などで1手法ずつ別フォルダへ取り込んでください。単独の旧結果で入力・実行との対応を証明できない場合は、その限界を取込記録と解析レシートに保存します。RDS構造の検証成功を、元解析条件まで検証済みという意味にはしません。

取込と同時に既存サブプロジェクトの再利用先へ登録するには、同じコマンドに `--project-id ID --subproject-id ID` を指定します。登録後、「現在の条件で下流解析」を使います。取込だけでは新しいUMAP・クラスタは計算しません。

診断は再出力で対応できる結果、下流再計算が必要な結果、上流からの再計算が必要な結果を区別します。二つの旧Parquet列が同じPCA由来の場合、名前だけを直してPCA対Harmonyの比較へ変換することはしません。各手法の原RDSから再出力してください。

元の測定値が保存されていない結果でDEGに必要なデータを確認できない場合、DEGの完成を保証しません。検証できない設定や欠けたデータを推測で補うことはありません。旧アプリへ戻す場合は保持した旧結果を使い、新しい形式を旧版で上書きしないでください。
