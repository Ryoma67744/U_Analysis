MSI Analysis Application - セットアップガイド

別の PC でアプリケーションを実行するための環境構築手順です。

本アプリは Windows / macOS / Linux で動作します。本ガイドの前半は Windows 向け、 末尾に macOS 向けセクション・ Linux 向けセクションを記載しています。

必要なもの

ソフトウェアバージョン必須?用途
Python3.10 以上必須Web アプリケーション本体
R4.4 以上解析を行う場合のみUMAP 解析・クラスタリング・DEG 検出
R が不要なケース: 他の PC で解析済みの RDS ファイルを持ち込んで、 インタラクティブ可視化（UMAP・Spatial Mapping・Feature Plot 等）のみ利用する場合は R は不要です。

Step 1: ZIP ファイルの展開

1 MSI_Analysis_App_v2.1.0.zip を任意のフォルダに展開（解凍）します。

注意: パスに日本語（全角文字）が含まれるフォルダは避けてください。 例: C:\MSI_App\ のような英数字のみのパスを推奨します。 デスクトップ（C:\Users\ユーザー名\Desktop）は日本語ユーザー名の場合に問題が起きることがあります。

Step 2: Python のインストール

2 Python がまだインストールされていない場合は、以下からダウンロードしてインストールします。

ダウンロード: https://www.python.org/downloads/

重要: インストール時に 「Add Python to PATH」 に必ずチェックを入れてください。 これを忘れると、コマンドプロンプトから Python を実行できません。

インストール後、コマンドプロンプトで確認:

python --version
# 出力例: Python 3.12.2

Step 3: R のインストール（任意）

3 UMAP 解析・クラスタリングを実行する場合は R もインストールします。

ダウンロード: https://cran.r-project.org/bin/windows/base/

インストール先はデフォルト (C:\Program Files\R\R-4.x.x) を推奨します。

R のインストールパスがデフォルトと異なる場合は、展開したフォルダ内の .env.example を .env にコピーし、 R_HOME の値を実際のパスに書き換えてください。

Step 4: セットアップの実行

4 展開したフォルダ内の setup.bat をダブルクリックします。

自動で以下が実行されます:

  1. Python の存在チェック
  2. Python パッケージのインストール（Dash, Plotly, pandas 等）
  3. R の存在チェック（見つからない場合はスキップ）
  4. R パッケージのインストール（Seurat, harmony 等 — 初回は10〜20分かかります）
Python パッケージのインストールにはインターネット接続が必要です。 初回は 2〜5 分程度かかります。

Step 5: アプリの起動

5 フォルダ内の run_app.bat をダブルクリックします。

コマンドプロンプトに以下のようなメッセージが表示されたら起動完了です:

Dash is running on http://127.0.0.1:3838/

ブラウザが自動で開きます。開かない場合は、ブラウザで http://127.0.0.1:3838/ にアクセスしてください。

起動成功! ブラウザにアプリの画面が表示されれば、セットアップは完了です。

データの配置

解析データは以下のフォルダに配置します:

データ種別配置先
TIMS-MSI データData/TIMS/Data/
DESI-MSI データData/DESI/Data/

アプリ内のファイルブラウザから任意のフォルダを指定することも可能です。

トラブルシューティング

「Python が見つかりません」と表示される

  • Python のインストール時に「Add Python to PATH」にチェックを入れたか確認してください
  • コマンドプロンプトを一度閉じて開き直してください（PATH の反映に再起動が必要な場合があります）

「pip install に失敗した」と表示される

  • インターネット接続を確認してください
  • プロキシ環境の場合は、IT 部門に pip の設定方法を確認してください

ブラウザに画面が表示されない

  • コマンドプロンプトにエラーメッセージが出ていないか確認してください
  • ポート 3838 が他のアプリで使用されている可能性があります。.env ファイルで APP_PORT を変更できます

R の解析が実行できない

  • R が正しくインストールされているか確認: コマンドプロンプトで Rscript --version
  • .env の R_HOME が実際のインストールパスと一致しているか確認
  • setup.bat を再実行して R パッケージをインストールしてください

macOS でのセットアップ

macOS (Intel / Apple Silicon どちらも対応) では run_app.sh / setup.sh を使用します。

Step M-1: Python のインストール

どちらかの方法で Python 3.10+ を導入します。

  • Homebrew (推奨): 
    brew install python@3.11
  • 公式インストーラ: https://www.python.org/downloads/macos/ 
python3 --version
# 出力例: Python 3.11.x

Step M-2: R のインストール（任意）

解析を実行する場合のみ必要です。ビューア機能だけなら不要です。

  • Homebrew: 
    brew install --cask r
  • CRAN 公式: https://cran.r-project.org/bin/macosx/
    インストール先: /Library/Frameworks/R.framework/Resources (既定)
CRAN 公式インストーラの既定パスは config.py がデフォルトで認識します。 Homebrew 版は PATH 上の Rscript を自動検出するため、追加設定なしで動作します。 それ以外のパスにインストールした場合は .env で R_HOME を指定してください。

Step M-3: ZIP の展開とセットアップ

配布 ZIP (MSI_Analysis_App_v2.1.0.zip) を任意のフォルダに展開し、ターミナルで以下を実行します。

cd /path/to/App
./setup.sh

自動で以下が実行されます:

  1. Python 存在チェック
  2. Python パッケージのインストール
  3. Rscript 存在チェック (見つからない場合はスキップ)
  4. R パッケージのインストール (初回は 10〜20 分)
実行ビットが外れている場合: 配布 ZIP には実行ビット (0o755) を付与していますが、Finder の解凍ユーティリティや 一部の解凍ツールでは属性が落ちることがあります。エラー Permission denied が出た場合は以下を実行してください: 
chmod +x run_app.sh setup.sh
もしくは直接 bash で起動することもできます: 
bash setup.sh
bash run_app.sh

Step M-4: アプリの起動

./run_app.sh

起動後、ブラウザで http://127.0.0.1:3838/ にアクセスします。

Gatekeeper の警告が出た場合: .sh はシェルスクリプトのため通常ブロックされませんが、 もし起動しない場合は python3 run_app.py を直接実行することもできます。

macOS トラブルシューティング

Rscript が見つからない (Homebrew でインストール済みなのに)

  • which Rscript で PATH 上に存在するか確認
  • Apple Silicon で Homebrew 版を使う場合、/opt/homebrew/bin が PATH に入っている必要あり (zsh なら ~/.zshrc に eval "$(/opt/homebrew/bin/brew shellenv)")

Seurat / harmony のビルドに失敗する

  • Xcode Command Line Tools が必要: xcode-select --install
  • Apple Silicon では R 4.4 以降を推奨 (arm64 ネイティブバイナリが提供されています)

Linux でのセットアップ

Ubuntu / Debian 系の例:

sudo apt install python3 python3-pip r-base
cd /path/to/App
./setup.sh
./run_app.sh

それ以外のディストリビューションでも、Python 3.10+ と R 4.4+ が入っていれば同じ手順で動作します。 Docker 経由で実行する場合は、プロジェクトルートの Dockerfile / docker-compose.yml を使用してください。
