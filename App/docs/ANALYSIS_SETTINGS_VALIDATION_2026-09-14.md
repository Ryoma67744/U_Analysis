# 解析設定整理の検証記録

## 比較元

比較元は main `8c461724b6143d7d8fd641586e0cc5992bb234d7`。別 worktree で未変更版に
`python3 -m pytest tests --ignore=tests/e2e -q --tb=short` を実行した。

- 2,950 passed、3 failed、46 skipped、2 xfailed（81.98 秒）。
- 失敗は `test_job_registry.py::TestConcurrencyGuard` の二重起動・保守ツールとの排他・同時起動の 3 件。
- 検証環境では子プロセス PID と `/proc` の PID 空間が異なり、`Popen.poll()` と signal 0 で
  生存中の子プロセスを `psutil.Process(pid)` が別プロセスまたは存在しない PID と判定した。
  main でも再現し、今回の変更による回帰とは区別する。
- R を利用可能にすると、同じ理由で実 Rscript の生存検知試験も失敗する。

## 実アプリの登録・ボタン応答

`test_settings_runtime_callbacks.py` はアプリを一時領域へ複製し、実際の Dash 登録と
認証後の Flask HTTP コールバックを実行する。利用者の保存設定・認証情報は変更しない。

- レイアウトの ID 重複、コールバックキーの重複、コールバックが登録されていないボタン。
- 初回解析・再解析それぞれの全選択／全解除。
- 別ファイルの同名 ROI を個別に選択する処理。
- 選択行だけへの群名一括割当と、その結果・通知の返却。
- DB 照合とキャリブレーションに対応する設定表示。

初回の実起動監査では、設定画面とインタラクティブ画面の `section_group_table` の
重複を検出した。インタラクティブ側の ID を分離し、復元後にも上記 4 試験の成功を確認した。

## 実 Seurat マーカー試験

`test_desi_marker_assay_runtime.py` は、測定値と符号が逆の補正アッセイを持つ
小型 Seurat オブジェクトを使用する。図の保存だけを省略し、実際の `FindAllMarkers` で
測定値に対応する fold change の方向と p 値を確認する。

環境再起動前および最終復元後の試験は成功した。Spatial への復帰を integrated に戻した
変異版では意図した検査に失敗し、回帰検出能力を確認した。

## ブラウザ検証の範囲

通常の Chromium を公式 Debian パッケージから取得して依存を解決したが、
起動時に環境制約の `socket() Operation not permitted` で停止した。
Browser skill の cloud ブラウザも、隔離アプリの localhost へのアクセスが
`ERR_BLOCKED_BY_CLIENT` で拒否された。本番環境のログインや設定には触れていない。

したがって、上記の HTTP コールバック検証を、ブラウザ上の DOM クリックや目視確認が
完了した証拠としては扱わない。

## 小規模入力を用いた実解析と保存物の照合

R 4.5.3、Seurat 5.5.1、Harmony 2.0.5、arrow 25.0.0、qs 0.27.3 を使用した。
R解析は直列で実行し、`DEG_WORKERS=1` と BLAS/OMP の1スレッド設定を使用した。
これは検証環境の資源制限への対応で、正規化・クラスタ・RPCAの解析条件は変更していない。
入力は固定乱数による合成データで、利用者の実試料ではない。

| 実行ケース | 保存結果と確認内容 |
| --- | --- |

| TIMS：ROI1だけの1切片、120画素 | PCAの下流出力が完成。Harmony・RPCAは統合単位不足として未実行。 |

DESIの最初の停止は検証側の時間制限による強制終了であり、製品コードの例外ではない。
中断後は保存条件・署名を継承し、PCA・Harmony座標が中断前／reduction保存／続行後で
一致することを実Rで確認した。通常のTIMS実行とDESIの続行・再解析では、3手法が
すべて下流処理まで完成した。

各手法の保存RDSを読み直し、次の内容を照合した。

- RDSのクラスタと画素表・クラスタCSVの割当が一致すること。
- TIMSの描画用保存UMAP座標がRDSと一致し、マーカー表が同じクラスタ定義を参照すること。
- DESIのcell_metadata、マーカー所属、UMAP画像が揃い、RDSと同じクラスタを使うこと。
- 再解析の元ファイルID・元画素ID集合が、指定した切片／クラスタの積集合と一致すること。
- 同名6ファイルでもファイル別ROI選択、6個の表示・H&E対応キーが衝突しないこと。
- DESIの6切片でCtrl／case各3独立試料が全結果へ継承されること。

## 実行中に発見して修正したUMAPマージ不具合

DESI再解析後の実マージで、サブクラスタ名が `NA-a`／`NA-b` になる問題を検出した。
親クラスタの無名ベクトルを画素名で参照していた箇所を、メタデータの行名参照へ修正した。
保存済みRDSからマージ処理だけを再実行し、264画素の親名が正しい元クラスタに対応すること、
未対象954画素のクラスタ・UMAP座標、および全画素の由来・群・表示メタデータが
変わらないことを確認した。実Rの回帰テストも追加した。


## 続行ボタンの表示と保存条件

推奨値を反映する③と、保存条件を継承する④の役割が従来の説明では混同されていたため、
③は新しい解析への反映、④は保存条件での続行と明記した。続行出力には未使用の画面値を
含めず `_continued` を使う。旧形式の保存済みフォルダは引き続き読み込める。

対象66試験が成功し、③が4個のUMAP設定を更新して新しい解析で使われること、④では保存済み
条件が実際に継承され、確認ダイアログと実際の出力先が一致することを確認した。
R処理や数値計算は変更していない。
