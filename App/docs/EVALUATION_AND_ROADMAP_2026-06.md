対象アプリ：U_Analysis（TIMS・DESI MSI を UMAP で解析・探索・共有する研究室向け Web アプリ。R 解析スクリプト群＋Python/Dash UI）
作成日：2026-06-30
位置づけ：先行 2 レポート（① 公開実装との比較分析、② 自己評価 7.4/10 の統合回答）を、**実コード**と**最新の公開情報**に突き合わせて精査し直し、改善の優先順位を確定するための文書。
方針メモ：本文書は調査結果のまとめであり、**この段階ではアプリのコード・解析スクリプト・設定は一切変更していない**。各改善項目の実装は項目ごとに別途承認のうえ着手する。プログラミング用語は最小限にし、機能・考え方・研究上の意味を中心に説明する。

## 1. エグゼクティブサマリー

**結論を一言で：2 本のレポートの方向性は正しい。ただしアプリは、レポートが想定している以上に、すでに土台が出来上がっている部分が多い。** したがって今後の改善は「ゼロから新規に作る」よりも「**すでにある仕組みに、あと少し足す**」ものが中心になる。これは着手コストが小さく、優先順位も変わる。

特に、レポートが「無い／弱い」と評価した次の 5 点は、実際には**土台が実装済み**だった：

1. **解析の記録（来歴）**：解析するたびに、入力・UMAP 設定・しきい値・時刻などの「設定の控え」が自動保存されている。
2. **「これは探索的な順位付けで、群間の結論ではない」という注意書き**：TIMS の解析ではすでに表示されている（表の列と図の副題）。
3. **H&E（病理像）の位置合わせ**：手動の位置合わせと「どれだけズレているか」の誤差数値が、裏ですでに計算されている（画面に出していないだけ）。
4. **大きなデータの表示**：必要な部分だけ読む・後回しで読む・結果を使い回す、といった高速化はすでに実装されている。
5. **共有・安全性**：期限／パスワード／取り消しのできる共有リンク、安全なパスワード保管、アクセス記録は、すでにある。

逆に、**本当に足りない（＝改善の本丸）**のは次の通り：

- アノテーション（代謝物名）が手元の表との照合だけで、**外部結果の取り込みと「何で付けた注釈か（由来）の表示」が無い**。
- クラスタの**安定性チェック**（偶然できた塊でないかの確認）が無い。
- 点（pixel）単位の検定結果を、**領域・標本ごとにまとめ直して「論文で主張できる差」にする**仕組みが無い。
- 共有の**役割分け（閲覧者／編集者）・重要操作の記録・多要素認証**が無い。
- imzML（標準形式）非対応、自動テスト・部品バージョン固定が無い。

**改善の方針**：見た目を大きく増やすのではなく、「結果を読み違えないための安全装置・根拠・再現性」を足す。優先は**科学的信頼性**から。到達見込みは、先行レポート②の見立て（主要強化で 8.3〜8.7/10）と整合する。

## 3. 現状検証：レポートの見立て vs アプリの実態

| レポートの見立て | アプリの実態 | 捉え直し |
|---|---|---|
| 来歴・記録（provenance）が弱い | 解析ごとに**設定の控えが自動保存**（入力・UMAP 設定・しきい値・calibration・時刻など） | ゼロからではなく**「控えに項目を足す」**。不足：使ったソフトの版、乱数の種、クラスタ/正規化/補正の細かい設定、入力データの照合値（ハッシュ）、出力一覧 |
| 探索的ランキングである旨の注意書きを足すべき | **TIMS は表示済み**（表の列「ranking_type / inference_note」＋ Volcano 副題に「pixel-level の探索的順位であり sample-level 推論ではない」） | **「同じ注意書きを広げる」**だけ。DESI・画面・PPTX・共有ページには未表示 |
| H&E は重ねるだけ・精度評価が無い | **手動ランドマーク位置合わせ＋ズレ量（RMS 誤差）が裏で計算済み**（UI 非表示）、位置合わせ情報は保存済み | 誤差数値の**画面表示は即可能**。自動化・変形補正・本格的な精度指標（Dice / Hausdorff / rTRE）が本当の不足 |
| 大規模表示が弱い | **必要列だけ読む・重い計算は後回し・結果を使い回す（cache）＋ WebGL 描画**を既装 | ほぼ達成済み。タイル/詳細度切替・サーバ側絞り込みは“あれば良い”レベル |
| 共有・安全性が弱い | 期限/パスワード/取り消し付き共有リンク、安全なパスワード保管（bcrypt）＋セッション失効、全アクセスの記録を既装 | 土台あり。**役割分け（owner/editor/viewer）・per プロジェクト権限・重要操作のイベント別記録（改ざん耐性）・失敗回数制限・多要素認証**が不足 |
| アノテーションが m/z 照合だけ | その通り（手元の表との突き合わせのみ）。**外部結果の取り込みと「何で付けた注釈か（由来）の表示」が無い** | **新規＋拡張**。最優先（ただしアプリ側で良し悪しの判定＝診断はせず、**由来の表示**が主） |
| imzML（標準形式）非対応 | その通り（完全に未対応） | 新規 |
| 自動テスト無し・部品の版が未固定 | その通り（R は最新を都度取得、Docker 基盤も最新タグ、認証/共有/記録に単体テスト無し） | 再現性・運用の地盤補強 |

## 4. 公開情報の照合（訂正・最新化・見落とし）

### 4.1 アノテーション
- **METASPACE-ML の件数の食い違いは“矛盾していない”**。①「930 件 / 47 labs」と ②「1710 件 / 159 researchers / 47 labs」は、**1710＝全体、約 780＝学習用（動物 600＋植物 180）、約 930＝評価用**という内訳の違いにすぎず、両方とも正しい。
- ① の「単一の決定木」は誤り。正しくは**多数の決定木を束ねた機械学習（勾配ブースティング）**。信頼度（FDR）は**段階値（5% / 10% / 20% など）**であり、なめらかな連続値ではない。1 つの当たり（分子式＋付加体）に**複数の候補分子**がぶら下がる点も重要で、名前を一意に断定はできない。
- **取り込みが“技術的に”最も容易なのは METASPACE**（専用の取得手段で候補名・FDR・スコアまでまとめて受け取れる）。ただし**本アプリの優先順位は科学的重要度に合わせ、LC/MS 照合を第一**とする（METASPACE は容易なので第二として早期併走可能）。
- **MS-DIAL は現行が新版（v5、2024）**で MSI 対応・標準形式出力が増えた。取り込むなら**標準形式の出力**を使うのが堅実。

### 4.2 UMAP・クラスタ安定性
- 種を固定すると並列処理を実質止めることになり、その代わり毎回まったく同じ図になる（公式仕様）。アプリは種を固定済みだが、**「完全再現モード」では並列を切る設定＋使用ソフトの版の記録**を足すべき。
- 一番安価で正当な安定性指標は「**別の種・一部抜き取りでやり直して同じ塊が残るか**」を一致度（ARI）・近傍保存度・シルエットで見る方法。**新手法 scICE（2025）**は先行レポートで見落とされていた。
- 「クラスタの一致度 0.6 未満は不安定／0.85 以上は安定」という UI 目安は実在する妥当な経験則。

### 4.3 空間統計（pixel か sample か）
- 隣り合う点は似て当たり前（空間的自己相関）なので、点単位の検定は“水増し”になりやすい。**点単位は「探索の順位付け」に限定し、結論は領域・標本ごとにまとめ直してから比較する**のが正しい。
- これを裏づける新しい論文（**pseudobulk ≒ 混合モデルで、しかも高速**、2024）は見落とされていた。アプリには**領域ごとに平均をとる部品が既にある**ので、まとめ直し（pseudobulk）の土台になる。
- 特徴ごとの**空間的まとまり度（Moran's I）**は軽く計算できる。MSI 画像に直接使える純 Python の道具（Moran_Imaging, 2025）も新たに登場（成熟度は発展途上）。

### 4.4 来歴・再現性
- 重い国際規格をフルで入れる必要はない。**まずは「項目をそろえた 1 つの控え（人が読める＋再現に十分）」で十分**。将来、その控えを標準形式（RO-Crate 等）へ“昇格”できる設計にしておけばよい。前処理の必須記録項目の出典は最新版（MIAMSIE / MSIcheck, 2018）に直す。

### 4.5 imzML・フォーマット
- 取り込み用の部品はある（小規模対応）。将来像として、**画像と病理を統合できる新しい保存形式（SpatialData / OME-Zarr、2025〜2026、ローカル imzML を変換する Thyra）**が有望で、これも先行レポートでは手薄。

### 4.6 H&E registration
- **最も軽い道具（SimpleITK）**だけで、手動・自動・変形・精度評価・保存まで一通り賄える。重い選択肢（VALIS 等）は後回しでよい。先行研究（msiFlow）は「**UMAP 画像を“基準”にして病理像を合わせる**」本アプリと同じ発想を実証している。

### 4.7 大規模表示
- 高解像度 MSI が巨大になる（例：120GB）という話は“全データを一度に読む設計”に固有の問題で、**本アプリは必要列だけ読む設計で既に回避済み**。最も効くのは**結果の使い回し（サーバ側 cache）の徹底**と、点が多すぎる時の間引き。Vitessce 等は発想の参考（全面採用は再実装が必要）。

### 4.8 セキュリティ
- 参照規格が新しくなっている（**ASVS 5.0、NIST 認証指針 800-63B は 2025 年確定版**）。小規模研究室では、**失敗回数の制限・セッション自動失効・重要操作の記録・管理者だけ二要素認証**が費用対効果の高い対策。共有の「取り消し」を本当に効かせるには、サーバ側での失効が前提。

## 5. 改善ロードマップ（科学的信頼性を優先）

見た目を大きく変えず、「結果を読み違えない安全装置・根拠・再現性」を足す。上から着手する。各項目の実装は**個別承認のうえ着手**する。

### 5.1 最優先（短期）

**(1) アノテーション：「何で付けた注釈か」の表示を主軸に**
- アプリは名前の良し悪しを**判定（診断）しない**。各特徴（m/z）に対し、**外部結果を取り込んで一致させ、「どの方法・どの実験で付けた注釈か（由来）」を表示する**だけにする。
- 優先順位：**① LC/MS 照合（同一・隣接切片や抽出液の LC-MS/MS 結果と m/z で対応づけ）→ ② METASPACE → （③ MS-DIAL）**。加えて手動ラベルも可。
- 表示は「由来ラベル」が中心：例「LC-MS/MS 由来」「METASPACE 由来」「MS-DIAL 由来」「手動」。**出典がもともと持つ指標（METASPACE の FDR 等）は“そのまま併記”**するが、アプリ側で新たに信頼度を採点したり A〜F 等に格付けする仕組みは作らない（過剰実装・過剰解釈を避ける）。
- 1 つの m/z に複数候補が付く場合は候補を併記（断定しない）。LC は保持時間（RT）等を“支持情報”として併記できるが、MSI 側は基本 m/z 対応である旨を明示する。
- 研究上の意味：論文図での「過剰同定」リスクを下げつつ、実装と保守の負担を最小化する。

**(2) 記録：「1 つにまとまった控え」に**
- バラバラのログではなく、**解析ごとに 1 ファイルへ集約**する。条件は (a)**目で見て分かる**（人が読めるレポート）、(b)**その 1 つがあれば再現できる**（必要な全条件を内包）、の 2 点。
- 既存の「設定の控え」を母体に、不足項目（**使用ソフトの版・乱数の種・クラスタ/正規化/補正の設定・入力データの照合値・出力一覧・使用したアノテーションの由来**）を足す。
- 結果フォルダから 1 クリックで開ける・落とせるようにする。将来、標準形式（RO-Crate）への書き出しも同じ項目から拡張可能にしておく。
- 研究上の意味：数か月後でも同じ図を再現でき、共同研究者・査読者の「どの条件で作ったか」に即答できる。

**(3) 「探索」と「結論」の統計分離**
- 点単位の注意書き（TIMS で実装済み）を、**DESI・全画面・PPTX/出力・共有ページに統一表示**する。
- 各特徴に**空間的まとまり度（Moran's I）**を付け、探索の順位付けと QC に使う。
- **領域・標本ごとにまとめ直した比較（pseudobulk → サンプル単位の検定）**を足し、“論文で主張できる差”を出す。既存の「領域ごと平均」部品が土台。
- 研究上の意味：点数の多さによる見かけの有意差を抑え、査読耐性が上がる。

### 5.2 重要（中期）

**(4) UMAP・クラスタの安定性パネル**
- 種やパラメータを変えて何度か計算し、一致度（ARI）・近傍保存度・シルエット・クラスタ一致度（0.6/0.85 目安）を表示。
- 各クラスタに**「安定／要注意／不安定」の旗**を立て、不安定なものは差分解析の候補から外せるようにする。
- 「完全再現モード」（並列を切る）＋ 種・版の記録（(2) と連動）。
- 研究上の意味：「1 枚の図の形」に意味を読み込みすぎる誤りを防ぐ。

### 5.3 発展（長期・科学コア確立後）
- **H&E 精度表示**：まず既存のズレ量（RMS 誤差）を画面に出す（即効）。次に軽い道具（SimpleITK）で変形補正・精度指標（landmark 誤差・重なり度）・変換の保存を追加。「UMAP 画像を基準にする」発想を採用。
- **imzML・標準フォーマット**：取り込み（と必要なら出力）に対応。将来 SpatialData / OME-Zarr。
- **共有・権限・監査**：役割分け（owner/editor/viewer）、重要操作の記録（標準イベント語彙・改ざん耐性）、共有制御（既定非公開・期限・失効・ダウンロード制御）、失敗回数制限・セッション上限、管理者の二要素認証。ASVS 5.0 を確認チェックリストに。
- **大規模表示の総仕上げ**：結果の使い回し（サーバ側 cache）の徹底、点が多い時の間引き、必要なら画像のタイル化。

## 6. 確認方法（実装フェーズで使う観点）

- **アノテーション**：外部結果（まず LC/MS、次に METASPACE）を取り込み、各特徴に正しい由来ラベルが付くか。出典の指標（FDR 等）がそのまま併記されるか。
- **記録**：同じ入力・同じ控えで再実行し、出力・注釈数・種固定時の UMAP 座標・統計が一致（または許容範囲内）か。控え 1 ファイルだけで再現に必要な情報が揃っているか。
- **統計分離**：ラベルを入れ替えて偽の差を作ったとき、点単位では“水増し”が起き、領域・標本でまとめると収まるか。注意書きが全出力面に出るか。
- **安定性**：同じデータで種を約 20 回変え、クラスタ一致度・近傍保存度の分布を記録し、旗（安定/要注意/不安定）が妥当か。
- **H&E・共有・形式**：誤差バッジ表示、位置合わせ精度指標、imzML 読み込みの整合、共有記録から「ある図に至る操作列」を逆にたどれるか。
- 既存のテスト基盤を活用し、認証・共有・記録の単体テストは新規に追加対象とする。
