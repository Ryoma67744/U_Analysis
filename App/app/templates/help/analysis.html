📁 2. データ準備

解析の前提として、生データを サーバー上の固定パス に配置する必要があります。

図2: SFTP直アップロード → サーバー固定パス → アプリ表示 のデータフロー

SFTP接続の詳細手順

WinSCP / Cyberduck のインストールから初回接続までの手順は、 App/docs/SFTP_GUIDE.md を参照してください。 接続情報（ホスト名・ユーザー名・パスワード）はサーバー管理者から取得します。

⚠️ フォルダ命名規則
サンプルフォルダ名は ASCII英数 + アンダースコア を推奨します（例: sample_001, 250621_Ohashi）。 日本語・スペース・特殊文字を含むと、R スクリプトの読み込みで文字化けや失敗の原因になります。

⚙️ 3. 解析設定タブ

サブプロジェクトを開くと、まず「解析設定」タブが開きます。画面は サイドバー（左）+ メインパネル（右） 構成です。

🚀 標準フロー（手法別の一般的な流れ）

もっとも一般的な使い方です。各手法を選ぶと、設定画面にも同じ内容の推奨バナーが表示されます（選択中の手法のものだけ）。

💡 TIMS × SCiLS RMS の標準フロー
  1. TIMS データを SCiLS RMS で出力
  2. 正規化 「OFF」（INPUT_NORMALIZED=TRUE）＋ 変換 log1p ＝ RMS×TIC の二重正規化を回避（TIMS は既定でこの設定）
  3. サンプル数で自動分岐：1サンプル→PCAのみ／複数→Harmony・RPCA （両方算出。「クラスタソース」で下流に使う手法を選択）
  4. UMAP・クラスタリング
段階比較が目的なら未補正(PCA)も併用。各条件1切片は交絡に注意（→7章）。
💡 DESI（生データ）の標準フロー
  1. DESI データ（生データ）を入力
  2. 正規化 「ON」（LogNormalize＝TIC正規化＋log。DESI は既定でこの設定）
  3. サンプル数で自動分岐：1サンプル→PCAのみ／複数→Harmony・RPCA （ROIモードで各ROIを別サンプル化すると複数統合）
  4. UMAP・クラスタリング
段階比較が目的なら未補正(PCA)も併用。各条件1切片は交絡に注意（→7章）。

🧭 解析シナリオの選び方（TIMS）

TIMS の UMAP 解析設定にある「解析シナリオ（切片アノテーションの意味）」で、切片アノテーションが何を表すかを選ぶと、補正方法が自動で切り替わります（既定＝無補正PCA＝従来挙動。R 既定値は変更しません）。

シナリオ例行われる補正と出力（reduction）
同一切片のクラスタ／群比較1切片の部分構造／Ctrl vs KO が別アノテーション補正なし＝無補正PCA（条件が2つ以上なら condition 間 DEG も算出。各条件1切片は交絡注意）
連続切片を技術反復としてまとめる同一個体の連続切片RPCA で slice_id を統合（＋無補正PCA を併走出力）
切片間の測定差(バッチ)を補正【非推奨】測定ロット差を除きたいHarmony で slice_id を補正（＋無補正PCA を併走出力・過補正の恐れ）
条件比較＋技術差補正各条件1切片で測定間の技術差を均したいHarmony＋RPCA を両方 slice_id に適用（測定差を補正・条件差も縮小／＋無補正PCA を併走出力）
💡 再解析（exclusion/inclusion）と計算の再利用
  • 再解析タブにも同じシナリオ欄があり、既定で初回解析の選択を引き継ぎます（変更可）。
  • exclusion/inclusion は指定クラスタの pixel を取捨選択して部分集合で解析をやり直す（reduction も再計算）。条件は初回と揃えるのが推奨です。
  • 部分集合でパラメータを詰めるときは 「① reduction のみ作成 →（②診断・③反映）→ ④続きを実行」を使うと、部分集合の reduction を1回だけ計算して再利用し、UMAP/クラスタリングのみ再実行します。
  • 初回(全体)の reduction を部分集合へ流用することはしません（HVG/PCA/Harmony は細胞集団に依存＝科学的に別物のため）。

🆕 DESI ROI モード（複数 ROI を別サンプル扱い）

DESI 入力 .txt の 最終列に ROI 文字列 (例: Brain, Heart, LN, TDLN など) が含まれている場合、各 ROI を「別サンプル」として扱い Multi-sample mode（Harmony / RPCA）で統合解析できます。TIMS の annotation（slice_id）列ロジックと同等の機能で、ver2.0 で追加されました。

💡 想定データ形式

タブ区切り .txt。ヘッダー 4 行の後に spot_index, x, y, m/z_1, m/z_2, ..., m/z_N, ROI の順で並ぶ。

ROI 列は文字列。空欄や数値（例: 0）はそのまま「1 つの ROI」として 扱われる。ROI モード OFF（デフォルト）ならこの列は無視され、ファイル全体が 1 サンプルとして処理される。

操作手順

  1. 解析設定タブの DESI セクションで 「ROI 列があれば各 ROI を別サンプルとして解析」 トグルを ON にする
  2. データフォルダ直下に表示される ROI チェックボックス から、解析したい ROI のみ選択する（例: LN と TDLN にチェック、0 を外す）
  3. ▶ 解析実行
  4. R スクリプトのログに >> ROI モード ON: ... を 2 個の ROI に分割 (LN, TDLN) と出れば成功。Spot Filtering メッセージが ROI の数だけ繰り返される
入力データROI モード挙動
ROI 列なしOFF従来通り（1 サンプル）
ROI 列なしON警告ログ出力 → 1 サンプル扱いにフォールバック
ROI 列ありOFFROI 列は無視、ファイル全体を 1 サンプル扱い
ROI 列ありON各 ROI を別サンプル化 + Harmony/RPCA で統合
ROI 列ありON + ROI 選択選択した ROI のみを統合（その他は除外）
⚠️ メモリに注意
ROI を多く選ぶほどサンプル数が増えるため、Harmony / RPCA の統合計算で メモリを多く使います。25,000 spots を超える単一 ROI を含む場合、 spatial smoothing で OOM を防ぐため ver2.2 で内部しきい値を引き下げています （25K spots 以上は逐次計算に自動フォールバック）。

🆕 サンプル別の反転・回転（flip / rotation）

Spatial プロット（組織切片上のクラスタ表示）は、サンプルごとに 回転角度 (0/90/180/270°)・水平反転・垂直反転 を独立に設定できます。論文用に切片の向きを揃えたり、左右を統一したい場合に使います。

  1. インタラクティブタブ → Spatial プロット下のコントロール
  2. サンプルごとに「回転」セレクト / 「水平反転」「垂直反転」スイッチを操作
  3. プロットが即時に更新される。設定は interactive_settings.json に自動保存される（プロジェクト × サブプロジェクト単位で永続化）
💡 軽量ビューアへの反映
ver3.0 で 軽量ビューア（新タブ）も flip/rotation を即時反映 するよう修正されました。インタラクティブで反転・回転を設定した直後に 軽量ビューアを開くと、最新の設定が反映された状態で表示されます （内部的には、軽量ビューアを開く直前に Store → JSON への保存を完了させてから 新タブを開くシーケンスに変更）。

インタラクティブタブの 「🔗 軽量ビューアを開く（新タブ）」 ボタンで、 PPTX 出力と同等の構造を持つ レポート型サマリビュー を新しいタブで開けます。 URL は /lite/<project_id>/<sub_project_id> 形式で、 Tier A 認証下で常に最新の解析結果（UMAP, Spatial, Volcano, Cross-cluster Heatmap など） を素早く確認できます。

💡 PPTX 出力との違い

PPTX 出力は全画像をスライドに焼き込むので生成に時間がかかりますが、 軽量ビューアは Plotly のままブラウザ表示するので即時開きます。

Cross-cluster Heatmap が空表示になるバグは ver3.0 で修正されました （gene 名の dtype 不整合で reindex 後に全行 NaN 化していた問題を解消）。

📐 7. データの前提と結果の読み方（重要）

⚠️ このセクションの位置づけ
解析結果（PCA / Harmony / RPCA / UMAP）を正しく解釈するための前提をまとめています。 特に 「各発生段階＝1切片（反復なし）」 のような交絡データでは、補正結果の読み方を誤ると 技術差を生物差と取り違える恐れがあります。解析前・結果確認前に必ず一読してください。

7.1 データの前提（交絡）

典型例として、E14 / E16 / E18 / P0 などの発生段階を各1切片で測定し、 各切片を独立に取得（別ラン）、入力は SCiLS の RMS で正規化済み、というケースがあります。 この場合 「測定（ラン/切片）」と「生物条件（段階）」が1対1で対応＝交絡しています。

7.2 正規化（RMS / TIC / LogNormalize）

用語内容
GUI「正規化 ON」Seurat LogNormalize ＝ 各スポットを総量(TIC)で割る ＋ ×1e4 ＋ log1p（＝「TIC正規化＋α」）
RMS（SCiLS）各スペクトルを RMS=√(mean(強度²)) で割る。TIC の兄弟（per-spectrum スケーリング）。scRNA の library-size 正規化に相当
RMS済みの正しい設定GUI「正規化 OFF」(INPUT_NORMALIZED=TRUE) ＋ NORM_MODE=log1p（二重正規化を回避）
⚠️ RMS はバッチ補正ではない
RMS が消すのは「全体強度（明るさ）」のみ。m/z 個別の差・ドリフト・非線形応答などの構造的バッチは残ります。 scRNA で library-size 正規化をしても別途バッチ補正が要るのと同じで、正規化とバッチ補正は別レイヤです。

7.3 バッチ効果と交絡

  • 各段階1切片＝バッチが段階と完全交絡 → 技術差と生物差を数学的に分離できない（計算困難でなく原理的に不可）。
  • 空間トランスクリプトーム・メタボロミクス両分野の共通見解：「全条件が各1バッチなら補正不能。反復か共有参照（QC/内部標準）が必要」。
  • 発生空間アトラス MOSTA は各段階4〜6切片の反復を置いて交絡を回避している。

7.4 Harmony / RPCA の挙動と限界

  • 交絡下で段階をバッチとして補正すると、技術差と生物差を一体で除去（過補正）。両者を区別する機能はない。
  • 補正強度は概ね Harmony ＞ RPCA（パラメータ依存）。ただし強度差は技術/生物の分離器ではない（残差も差分も同じ技術:生物比の混合）。
  • 条件とバッチを分離する専用手法（scDisInFact 等）も multi-batch × multi-condition 設計が前提＝1切片/段階では使えない。

7.5 結果の読み方（PCA / Harmony・RPCA / UMAP）

ビュー映るもの段階の生物差として
未補正 PCA段階間差の全体（技術＋生物・交絡）＝「差」の面本命だが交絡。loading・QC で正体を吟味
Harmony / RPCA段階をまたぐ共有構造＝「共通性」の面（段階差は除去済み）差を読む図ではない。残る差情報は組成のみ（記述的）
💡 UMAP の見方
UMAP は近傍構造の可視化（探索）ツール。局所のグルーピング（共通性）は信頼でき、 大域距離（差の大きさ）は非定量です。見た目の分離を生物差の証拠にしないでください。 差の定量は PCA 分散・統計検定（DE 等）で行います。

7.6 解剖アンカーによる解釈

「解剖学的に同じ領域なのに ROI の色（クラスタ/発現）が違う」＝ 生物差の有力な候補です。 解剖は外部の生物学的アンカーで計算統合より頑健（「別構造だから違う」交絡を除ける）。 ただし「別測定（ラン=段階）」交絡は残るため、それ単独では候補であって証拠ではありません。

  • 状況証拠の固め方：差を駆動する特徴が (a) 発生的に妥当か、(b) 技術QC と無相関か。
  • 確証は反復／直交検証（既知マーカー・別手法・共有参照）。

7.7 推奨運用

  • 正規化：RMS済み → 「正規化 OFF」(INPUT_NORMALIZED=TRUE) ＋ NORM_MODE=log1p。生データの直入れは不可。
  • 表示：未補正(PCA)を必ず併記（基準・段階比較の本命）。Harmony/RPCA は「共通性」ビューと役割を明示。
  • 補正手法：交絡下では増やさない。見せるなら「補正なし→RPCA→Harmony」の強度スペクトルとして。
  • 診断：未補正 UMAP を総強度/QC で色分け（残存技術チェック）、組成ビュー、PreFlight の交絡判定（not_identifiable）を確認。

7.8 確証に必要なこと

⚠️ 確証には実験デザインが必要
各段階に反復切片（≥2）、または全ランで測る共有参照（プールQC/内部標準）があって 初めて、技術と生物を分離した「段階差」の主張・統計検定が可能になります。

B. 共有方式の選択（ver4.2: 期限とパスワードは独立）

サブプロジェクト一覧の「共有リンク作成」モーダルで、「有効期限の有無」と 「パスワード保護の有無」を別々に選べます （どちらの組合せでもインタラクティブ解析の全機能が開き、操作は元プロジェクトに保存されます）。

⏰
① 有効期限

期間付き共有（/share/<token>）: 7 / 14 / 30 / 90 日で自動失効

無期限共有（/view/<token>）: 期限なし

🔒
② パスワード保護

ON: 共有先は 共有パスワード（Tier B）でログインが必要

OFF: 認証なしで誰でも開ける（URL を知る人全員）

→ 計 4 通り（期間付き×パスON/OFF、無期限×パスON/OFF）から選べます。 既定は「パスワード保護 ON」です。

🛑 パスワード保護 OFF のセキュリティ — 重要

共有先は 操作可能・かつ変更が元プロジェクトに保存されるため、 パスワード保護 OFF は URL を知る第三者が元データを書き換えられることを意味します （期限の有無に関係なく）。URL は token_urlsafe(16)（128 bit）で推測は困難ですが:

  • 機密データや書き換えられたくない結果には パスワード保護 ON を推奨
  • URL を メール・チャット・公開リポジトリ に貼ると、その経路から操作可能になる
  • サーバーログや CDN キャッシュに URL が残る場合がある
  • 失効は、サブプロジェクト一覧の 「共有リンク管理」 から削除 （期間付き・無期限どちらも一覧・削除可能）

C. 共有 URL の作成手順

  1. サブプロジェクト一覧から該当プロジェクトを開く
  2. 「🔗 共有リンク作成」ボタンをクリック
  3. 「共有方式（有効期限）」 で 期間付き共有 または 無期限共有 を選ぶ （期間付きの場合は「有効期限」も選択）
  4. 「🔒 パスワード保護」スイッチで ON（共有パス必須）/ OFF（認証なし）を選ぶ。 OFF のときは警告 Alert を確認
  5. 「統合手法」を選択（all / Harmony / RPCA / PCA）
  6. 必要に応じてメモを入力
  7. 「共有リンクを生成」 → 表示された URL をコピーして共有
💡 統合手法「all」と個別選択の違い（ver4.1）
  • all（全手法を共有・既定）: 共有先は結果フォルダにある全手法 （Harmony / RPCA / PCA）を取得し、画面上部のセレクタで自由に切り替えられます。
  • 個別手法（Harmony 等）: 共有先にはその手法のみが表示されます （特定の手法だけ見せたいときに選択）。

🛟 10. よくあるエラーと対処法

🛑 Permission denied (/srv/msi/...)

原因: ユーザーが msi-lab グループに属していない

対処: 管理者に sudo usermod -aG msi-lab <username> を依頼 → 再ログイン

🛑 対応ファイルが見つかりません

原因: データフォルダのパスが間違っている／ファイル拡張子が想定外

対処: 「参照...」→ショートカットで正しいパスを選び直す

🛑 R script timeout

原因: 大規模データで R_ANALYSIS_TIMEOUT_SEC 超過

対処: .env の R_ANALYSIS_TIMEOUT_SEC を増やすか、サンプル数を減らす

🛑 vector memory exhausted

原因: Rのメモリ上限超過

対処: .env の R_MAX_VSIZE_GB を増やす or Docker mem_limit を引き上げる

🛑 編集ロック失効 (Lock expired)

原因: 30秒間の無操作でロック自動解放

対処: ページ再読み込み → ロック再取得 → 操作再開

🛑 解析画面が真っ白

原因: ブラウザキャッシュの古い JS が残存

対処: Ctrl+Shift+R で強制再読込

❓ 11. よくある質問 (FAQ)

❓ 解析の途中で停止できる？

はい。実行中に表示される「⏹ 実行停止」ボタンで中断可能。 ただし途中までの出力ファイルは残らないことが多いです。

❓ 別のラボメンバーが解析中だと、自分も使える？

使えます。各ユーザーのセッションは独立しており、別プロジェクトを同時に解析できます。 ただし同じプロジェクトの同じサブプロを編集すると、編集ロックが競合します。

❓ 結果をPNGでまとめてダウンロードしたい

結果閲覧タブの「📥 全画像をダウンロード」または、SFTPで /srv/msi/output/<プロジェクト名>/ をフォルダごと取得。

❓ プロジェクト管理の使い方は？

ランディングページでの操作（新規作成・復元・共有）は 🏠 登録画面ガイド を参照。

🧰 13. 保守・ツール（RDS軽量化 / 環境設定 / SCiLS 変換）

🧹 RDS 軽量化

過去に解析した .rds ファイルを一括で軽量化します。DietSeurat で scale.data を削除し、qs で高圧縮保存に変換します。旧形式の .rds はマジックバイト判定で透過的に読めるため、読み込み互換性は完全に保たれます。

  • 対象フォルダ: 指定フォルダ以下を再帰スキャン（qs 形式は自動スキップ）
  • Dry-run（既定 ON）: 書き込まずに削減見込みだけ表示
  • バックアップ（既定 ON）: <file>.rds.bak を残す
  • 対象ファイルパターン（既定 Step1*.rds,Step2*.rds,Step3*.rds,*_seurat*.rds）
  • 詳細設定: --keep-scale / --keep-graphs（通常は OFF。再解析時に再構築される）
💡 まず Dry-run で確認
初回は Dry-run（ON）で削減見込みを確認してから、OFF にして実行するのが安全です。 書き込みはアトミック置換で行われ、進捗バーとログがモーダル内に表示されます。

🔄 SCiLS データ変換

SCiLS Lab で Export した Intensity CSV + Spot CSV（+ 任意の Annotation CSV）が入った フォルダを指定すると、ヘッダ構造とサイズで役割を自動検出し Parquet に変換します （TIMS 解析の入力形式）。

  • 入力フォルダ: SCiLS 出力フォルダ
  • 出力先フォルダ: 既定は TIMS_DATA_DIR（変換後すぐ解析タブの候補に出る）
  • サンプル名: 出力ファイル名（拡張子は自動付与）
  • 詳細設定: 変換後に元 CSV を <BASE>_Transform/ へ移動 / Parquet を float32 で保存（容量半減）/ spot ブロックサイズ（既定 200）
